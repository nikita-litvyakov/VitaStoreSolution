# Офлайн-режим и синхронизация данных

## 1. Работа без связи

Приложение облачной кассы работает по принципу **offline-first**: продажа всегда идёт локально, поэтому обрыв
связи кассир не замечает. Касса не переключается в «аварийный режим» по тайм-ауту.

**Что хранится на планшете:**
- каталог и цены;
- баланс лояльности;
- очередь исходящих чеков — каждый чек сначала записывается сюда с уникальным ID.

**Что работает без связи:**
- **Наличные + фискальный чек — всегда.** ККТ печатает чек через HAL-агент на планшете по локальному драйверу.
  Фискальный накопитель хранит чеки до 30 дней, ККТ сама досылает их оператору фискальных данных.
- **Карта — пока жив хотя бы один канал.** При падении основного канала роутер автоматически переходит на
  резервный LTE. Без обоих каналов — только наличные.
- **Лояльность не блокирует покупку:**
  - начисление баллов считается централизованно, после срока возврата;
  - списание без связи — по кэшу баланса, не больше 30% суммы чека.

## 2. Синхронизация при восстановлении связи

Порядок: **сначала чеки, потом справочники.**

| Данные | Как синхронизируются | Почему нет потерь и конфликтов |
|---|---|---|
| Чеки | Фоновая отправка из очереди в бэкенд облачной кассы | Приём идемпотентен по ID — повтор не создаёт дубль. Чеки только добавляются, возврат — новый документ со ссылкой на исходный |
| Каталог и цены | Загрузка изменений с последней версии | При расхождении побеждает облако |
| Баллы лояльности | Сверка офлайн-списаний с балансом в облаке | Перерасход (те же баллы потрачены в другом магазине) уходит в минус и гасится будущими начислениями; потерю ограничивает лимит 30% |
| Продажи и остатки в SAP ERP | Через интеграционный слой | За минуты, а не ночным FTP |

## 3. Контроль

- Длительность офлайна и размер очереди каждого магазина видны в HQ.
- Сигнал приходит задолго до 30-дневного лимита фискального накопителя.
- Планшет диагностируется удалённо через MDM — без выезда инженера.

*Допущение:* лимит списания баллов без связи 30% кейс не задаёт.
